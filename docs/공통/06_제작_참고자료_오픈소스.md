# 제작 참고자료 · 오픈소스 정리 (모든 작품 공통)

> 시나리오 작성 → AI 드라마·웹툰·영상 제작에 쓸 수 있는 GitHub 오픈소스와 참고자료.
> 2026-11 기준으로 조사했다. 버전·라이선스·별 수는 자주 바뀌므로 **쓰기 전에 각 저장소에서 다시 확인**한다.

| 단계 | 하는 일 | 추천 도구 (오픈소스) | 이 프로젝트에서 쓰는 법 |

| ⑨ 전체 자동화 | ①~⑧을 한 번에 | Toonflow, huobao-drama, ViMax, Pixelle-Video | 시험 제작·속도 비교용 |

## 1. 시나리오·대본 작성

### Dramatron (Google DeepMind)
- 로그라인에서 시작해 인물 → 줄거리 → 장소 → 대사 순서로 **계층적으로** 대본을 만드는 공동 집필 도구.
- 사람이 단계마다 고치고 다시 생성하는 방식이라 우리 편집기 흐름과 같다.
- Colab 노트북으로 돌리며, 사용할 LLM은 직접 연결해야 한다.
- 🔗 [GitHub](https://github.com/google-deepmind/dramatron)
- 👉 **활용:** 우리 편집기의 "기획안 → 회차 훅 → 대본" 단계 나누기가 같은 원리다. 단계별로 따로 요청할수록 긴 이야기가 덜 무너진다.

### Open-Write
- 시나리오·소설·TV용 긴 이야기를 설계하는 오픈소스(Apache 2.0) 도구. 사람이 설계하고, 도구가 구조를 붙잡고 점검한다.
- 🔗 [소개 페이지](https://www.producthunt.com/products/open-write)

### Fountain (대본 표준 텍스트 형식)
- 아무 텍스트 편집기로 대본 서식을 쓸 수 있는 무료 오픈소스 마크업.
- `screenplain`으로 `.fountain` 파일을 PDF로 바꿀 수 있다: `pip install 'screenplain[PDF]'` → `screenplain --format pdf 1화.fountain > 1화.pdf`
- 🔗 [Wikipedia](https://en.wikipedia.org/wiki/Fountain_(markup_language)) · [리눅스 사용법](https://opensource.com/article/21/12/linux-fountain)
- 👉 **활용:** 숏드라마 대본은 Fountain으로 저장하면 어떤 대본 도구로도 옮길 수 있다.

### 대본 편집기
| 도구 | 특징 | 링크 |
|---|---|---|
| Beat | macOS용, Fountain 기반, 무료 오픈소스(GPL), Final Draft 가져오기·내보내기 | [GitHub](https://www.github.com/lmparppei/Beat) |
| KIT Scenarist | 자료조사·카드·대본·통계 모듈, .fdx/.fountain/PDF 내보내기 (GPL v3) | [소개](https://itsfoss.com/kit-scenarist/) |
| Better Fountain | VS Code 확장, 무료·크로스플랫폼, 실시간 공동 집필 | [GitHub](https://github.com/kortina/betterfountain) |
| Fount | 터미널용 Fountain 편집기 | [GitHub](https://github.com/BeetleBot/FountCLI/wiki) |

## 2. AI 숏드라마 올인원 (대본 → 영상 자동화)

### Toonflow ⭐ 가장 활발
- 소설·대본을 넣으면 인물 추출 → 각본 → 콘티 → 영상 합성까지 한 번에 처리하는 데스크톱 작업대.
- 무한 캔버스, AI 에이전트, 노드 방식이라 **컷 하나만 다시 뽑기**가 가능하다.
- 라이선스 표기가 자료마다 다르다(Apache-2.0 / AGPL-3.0) → **상업 이용 전 저장소 LICENSE 확인 필수.**
- 🔗 [GitHub](https://github.com/HBAI-Ltd/Toonflow-app)
- 👉 **활용:** 「그믐과 서리」 1~3화를 시험 제작해서 비용·품질 확인. 대본은 우리 편집기 결과를 넣는다.

### huobao-drama (화보 드라마)
- Go + Vue3 기반. 대본 생성, 캐릭터 디자인, 콘티, 영상 합성까지 전 과정 자동화.
- 🔗 [GitHub](https://github.com/chatfire-AI/huobao-drama)

### ViMax (홍콩대 HKUDS)
- 감독·각본가·제작자 역할의 **멀티 에이전트**가 아이디어에서 영상까지 만든다. MIT 라이선스.
- 🔗 [GitHub](https://github.com/HKUDS/ViMax)
- 👉 **활용:** "각본가 → 감독 → 촬영" 에이전트 분업 구조를 우리 편집기 다음 버전 설계에 참고.

### Pixelle-Video (알리바바 AIDC)
- 주제 하나로 대본 → 영상 전 과정을 자동화하는 짧은 영상 엔진. 디지털 휴먼, 이미지→영상, 모션 전이 파이프라인 포함.
- 🔗 [GitHub](https://github.com/AIDC-AI/Pixelle-Video)

### 그 밖
- **MicroDrama AI:** 에이전트 방식 마이크로 드라마 생성기 🔗 [README](https://raw.githubusercontent.com/Anil-matcha/Open-AI-Micro-Drama-Generator/main/README.md)
- **Shortify AI:** 한 줄 → 대본·콘티·다중 성우·1080p 영상 🔗 [GitHub](https://github.com/ycbing/Shortify-AI)
- **Tencent ScriptAgent:** 대화 → 영화 같은 영상 장편 생성 연구 🔗 [GitHub](https://github.com/Tencent/digitalhuman/tree/main/ScriptAgent)
- **GitHub 토픽 모음:** 🔗 [script-to-video](https://github.com/topics/script-to-video) — 숏드라마 대본 형식·훅·템플릿 저장소도 함께 있다.

## 4. 캐릭터·의상 일관성 (가장 중요)

### ComfyUI (노드형 이미지·영상 작업 도구)
- 대부분의 오픈소스 이미지·영상 모델을 노드로 연결해 쓰는 표준 도구.
- 🔗 [GitHub](https://github.com/comfyanonymous/ComfyUI)

### 캐릭터 고정 방법 3가지
| 방법 | 도구 | 언제 |
|---|---|---|
| 참조 이미지 편집 | Qwen-Image-Edit, FLUX Kontext | 캐릭터 시트 1장으로 다른 각도·장면 만들기 (학습 불필요) |
| LoRA 학습 | AI-Toolkit (Wan/Flux/Qwen LoRA) | 주인공처럼 계속 나오는 인물을 완전히 고정 |
| 연속 컷 일관성 | StoryDiffusion | 여러 컷에서 같은 인물 유지 (만화·영상) |

- **Qwen-Image-Edit로 LoRA 학습용 데이터셋 만들기 → AI-Toolkit로 학습** 하는 흐름이 많이 쓰인다. 🔗 [설명](https://weirdwonderfulai.art/comfyui/qwen-image-edit-can-create-character-consistent-lora-dataset/)
- 🔗 [AI-Toolkit](https://github.com/ostris/ai-toolkit)

### 만화·웹툰·콘티 생성
| 도구 | 특징 | 링크 |
|---|---|---|
| StoryDiffusion | 긴 연속 컷에서 캐릭터 일관성, 만화 생성 데모 | [GitHub](https://github.com/hvision-nku/storydiffusion) |
| DiffSensei | 캐릭터 이미지·컷 설명·레이아웃으로 만화 생성 | [논문](https://arxiv.org/html/2412.07589v2) |
| Story2Board | 학습 없이 표현력 있는 스토리보드 생성 | [논문](https://arxiv.org/html/2508.09983v1) |

- 👉 **활용 순서:** 의상 시트 → (Qwen-Image-Edit) 정면·측면·뒷모습 캐릭터 시트 → (AI-Toolkit) 여울·서리 LoRA → 컷 생성.
- ⚠️ 한복은 학습 데이터가 적어 **한푸·기모노로 새기 쉽다.** 부정 프롬프트(`hanfu, kimono, Chinese, Japanese`)와 핀터레스트 실물 사진 참조를 함께 쓴다.

## 8. 이 프로젝트에 적용하는 순서 (추천)

1. **시나리오 작성 편집기**에서 작품을 불러와 `기획안` → `회차별 훅 표` → `1화 대본` 순서로 생성.
2. 대본을 Fountain으로 정리해 저장 (숏드라마는 씬 단위, 웹툰은 컷 단위).
3. `인물 의상 시트`를 생성 → 핀터레스트 레퍼런스와 함께 ComfyUI로 **캐릭터 시트** 제작.
4. 주연 2명(여울·서리)은 AI-Toolkit로 LoRA 학습.
5. 웹툰: StoryDiffusion·ComfyUI로 컷 이미지. 숏드라마: 컷 이미지 → Wan 2.2 / LTX-2로 영상.
6. CosyVoice·IndexTTS2로 대사 → LatentSync로 립싱크.
7. ACE-Step으로 BGM → 편집.
8. 처음 1~3화는 Toonflow로도 같이 만들어 품질·비용을 비교.

## 9. 주의사항
- **라이선스:** Apache·MIT는 상업 이용이 비교적 자유롭고, GPL·AGPL은 수정·배포 시 소스 공개 의무가 있다. 모델 가중치는 코드와 라이선스가 다를 수 있다.
- **GPU:** 영상 모델은 대부분 14~24GB 이상 VRAM이 필요하다. 없으면 클라우드 GPU나 호스팅 API를 쓴다.
- **한국어·한복:** 중국·영어 중심 모델이 많다. 한국어 발음, 한복 고증은 반드시 사람이 검수한다.
- **저작권·초상권:** 실존 인물 얼굴·목소리, 기존 작품 캐릭터를 학습하거나 흉내 내지 않는다.
